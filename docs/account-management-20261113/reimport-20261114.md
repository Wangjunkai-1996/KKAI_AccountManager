# `remote_missing` 账号的显式重新导入

日期：2026-11-14

候选版本：`20261114T030748Z-reimport`

## 目的

当历史记录确认某个 AUTH 账号原来的 Sub2 关联已经不存在时，账号表提供一个明确的“重新登录并导入 Sub2”入口。这个入口用于用户主动重建远端账号，不能由自动巡检、旧交付任务、恢复任务或普通登录成功自动触发。

## 前置条件与交互

- 账号必须仍存在、不是官方已删除状态、当前不在登录中。
- 历史绑定必须是 `remote_missing`，并且保留原 `operation_id`；缺少旧关联标识时不会提交重建。
- 账号表“更多”菜单只在满足上述条件时显示该入口；普通导入、自动恢复和自动检测继续被阻断。
- 用户在交付参数对话框确认一次即可授权完整的“重新登录 → 重建 Sub2”流程；登录成功后不再弹出第二次确认。
- 取消参数、关闭对话框或页面状态变化都不会发送登录或导入请求。

## 参数和安全门禁

登录请求固定使用 `manual_attempt:true` 与 `auto_deliver:false`，因此登录阶段只更新 AUTH 凭据，不自动交付。参数优先使用该账号历史交付参数；没有历史参数时才使用平台默认值。单账号流程使用参数副本，不修改批量参数或平台默认值；“同时保存为平台默认参数”在该流程中隐藏并禁用。

登录成功后重新读取历史，并要求：账号状态为 `active`、凭据版本是安全整数且严格大于流程开始时的版本、绑定仍为 `remote_missing`、`operation_id` 与开始时一致。满足条件才发送一次：

```json
{
  "account_ids": [780],
  "delivery_options": {},
  "reimport": true,
  "expected_credential_version": 123,
  "expected_import_operation_id": "..."
}
```

后端使用当前缺失绑定、账号状态、凭据版本、导入操作标识和事务 CAS 做最终校验。绑定变化、旧版本、历史刷新失败、登录失败或取消都会停止流程，不会继续提交。导入请求超时或结果未知时只保留一次请求并提示刷新核对，不自动重发。

登录失败后仍保留“Sub2 关联不存在”的门禁，同时在账号行和“更多”菜单显示持久化的具体失败原因（例如“代理配置无效”及规范错误码）；登录成功过渡态不会被误标为失败。

## #780 及其他账号

本功能不会自动处理 AUTH #780，也不会因为页面刷新、定时巡检或旧任务而创建新的 Sub2 账号。只有用户明确点击该入口并完成一次参数确认，才会进入登录和重建流程。
